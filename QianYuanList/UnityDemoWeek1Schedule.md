# Unity Demo 首周开发排期表

## 文档目标

这份文档用于把 `UnityDemoTaskBreakdown.md` 进一步落成首周执行排期。

目标很明确：

用 `7` 天时间，把 Demo 从“还没开工”推进到“基础可玩原型成立”。

这里的首周目标不是做完整 Demo，而是完成 Demo 最关键的地基：

- 工程能跑
- 角色能动
- 敌人能刷
- 自动攻击成立
- 前 3 波能打
- 商店能进

## 一、首周总目标

### 1.1 一周后必须达到的状态

一周结束时，至少要做到：

- 可以从菜单进入战斗
- 玩家角色可移动
- 玩家会自动攻击
- 敌人会出生、追击、掉落材料
- 波次能正常切换
- 第 3 波后能进入商店
- 能买到武器或道具
- 能进入下一波

### 1.2 一周后暂不强求的内容

首周先不强求：

- 角色全量差异
- 全部武器都可用
- 全部道具都可用
- Boss 完整机制
- 最终 UI
- 最终音效
- 性能优化收尾

## 二、排期原则

### 2.1 优先顺序

每天的优先级都遵循：

1. 先做能跑通主循环的东西
2. 再做能提升验证效率的东西
3. 最后才做体验增强项

### 2.2 每日交付原则

每天结束时都必须有一个“可验证结果”：

- 不是写了多少代码
- 而是多了什么能运行的东西

## 三、首周排期

## Day 1：工程初始化日

### 当天目标

把工程骨架搭起来，确保项目可以稳定进入开发状态。

### 当天任务

1. 创建 Unity 工程
2. 确定渲染管线和输入系统
3. 按规范创建目录结构
4. 创建 `Boot / Menu / Battle` 三个场景
5. 建立基础启动流程
6. 把 `QianYuanExcel` 配置表放入 Unity 可读取目录

### 当天交付物

- Unity 工程
- 基础目录树
- 三个基础场景
- 能从启动场景进入菜单

### 当天验收标准

- 工程无启动级报错
- 场景切换正常
- 项目结构已经固定，不再临时堆文件

### 当天建议收尾

- 提交一次版本记录
- 写一份当前工程目录截图或说明

## Day 2：玩家基础系统日

### 当天目标

让角色在战斗场景里“活起来”。

### 当天任务

1. 做玩家移动
2. 做摄像机跟随
3. 做玩家基础属性容器
4. 做生命值、受击、死亡
5. 做基础碰撞
6. 预留拾取判定点

### 当天交付物

- 可控制角色
- 基础角色状态系统
- 死亡判定

### 当天验收标准

- 角色可以稳定移动
- 角色能掉血、能死亡
- 摄像机跟随无明显问题

### 当天建议收尾

- 在场景里放一个临时受击测试对象
- 能手动验证“受击 -> 掉血 -> 死亡”

## Day 3：自动攻击原型日

### 当天目标

把最核心的“自动攻击”打通。

### 当天任务

1. 做自动索敌
2. 做基础攻击计时
3. 做 1 把近战武器
4. 做 1 把远程武器
5. 做基础伤害公式
6. 做命中判定

### 推荐武器

- 近战：`Claw`
- 远程：`Feather Dart`

### 当天交付物

- 自动攻击系统
- 近战命中逻辑
- 远程投射物逻辑

### 当天验收标准

- 不操作攻击键，角色也会自动输出
- 近战和远程至少各有 1 把武器可用

### 当天建议收尾

- 用日志或简易 UI 显示伤害结果
- 确认攻击节奏没有明显卡顿

## Day 4：敌人与掉落日

### 当天目标

让战斗真正成立，能刷怪、能杀怪、能拿资源。

### 当天任务

1. 做基础敌人 `Stray Dog`
2. 做敌人追击逻辑
3. 做敌人接触伤害
4. 做敌人死亡
5. 做材料掉落
6. 做玩家拾取材料

### 当天交付物

- 基础敌人
- 敌人击杀链路
- 材料回路

### 当天验收标准

- 敌人能出生并追玩家
- 玩家能击杀敌人
- 敌人死亡会掉材料
- 玩家能拾取材料

### 当天建议收尾

- 临时统计“本局累计材料”
- 临时打印敌人击杀数量

## Day 5：波次系统日

### 当天目标

把战斗变成“有结构的战斗”，不是无尽刷怪。

### 当天任务

1. 读取 `WaveConfig`
2. 做波次计时器
3. 做刷怪控制器
4. 做前 3 波内容接入
5. 做波次结束判定
6. 做波次结束暂停或切换逻辑

### 推荐先接入的敌人

- `Stray Dog`
- `Shadow Puff`
- `Alley Snake`

### 当天交付物

- 波次控制器
- 前 3 波可运行

### 当天验收标准

- 能连续打完前 3 波
- 每波敌人组成有差异
- 波次倒计时和结束都正常

### 当天建议收尾

- 临时在屏幕显示当前波次编号
- 临时显示剩余时间

## Day 6：商店原型日

### 当天目标

把单局成长闭环接起来。

### 当天任务

1. 做波次后进入商店
2. 读取 `WeaponConfig` 和 `ItemConfig`
3. 随机生成商店内容
4. 做购买逻辑
5. 做材料扣除
6. 做“进入下一波”按钮

### 首批建议接入内容

- 武器：`Toy Rod`、`Claw`、`Feather Dart`、`Laser Pointer`
- 道具：`Dried Sardine Pack`、`Wheatgrass Pot`、`Scratching Board`、`Black Cat Amulet`

### 当天交付物

- 基础商店
- 武器/道具购买逻辑

### 当天验收标准

- 第 3 波后能进商店
- 能看到商品
- 能购买
- 能进入下一波

### 当天建议收尾

- 商品先用简单列表 UI，不要卡在美术上
- 优先保证购买结果能真实改变战斗

## Day 7：闭环整合日

### 当天目标

把前 6 天的内容串成真正的 Demo 原型。

### 当天任务

1. 修复前 6 天串联后的问题
2. 完成角色选择界面最小版
3. 接入首批 `4` 个角色
4. 接入首批 `8` 把武器
5. 接入首批 `10` 个道具
6. 测试从菜单到商店再到下一波的完整流程

### 推荐首批角色

- `Well Rounded`
- `Brawler`
- `Ranger`
- `Mage`

### 当天交付物

- 基础可玩原型
- 单局闭环初版

### 当天验收标准

- 玩家可以选角色
- 能完整打一局前 3 波并进商店
- 购买内容后战斗效果确实变化

### 当天建议收尾

- 打一个内部测试包
- 记录阻塞问题清单

## 四、首周结束后的状态判断

### 如果首周顺利

你应该进入第二周，继续做：

- 精英敌人
- 第 4 到第 8 波
- 道具触发逻辑
- 商店刷新与锁定
- Boss 原型
- 战斗 HUD

### 如果首周没做完

不要直接扩内容。

应该先补齐这些核心环节：

- 自动攻击是否稳定
- 敌人与波次是否稳定
- 商店是否稳定
- 购买结果是否真实生效

## 五、每日自检清单

每天结束时，至少检查：

1. 今天新增的功能是否真的能运行
2. 是否破坏了昨天能跑的内容
3. 有没有新增明显阻塞 Bug
4. 是否有临时写死逻辑需要记录
5. 是否应该提交一次版本记录

## 六、首周最重要的控制点

你这一周最需要控制的是：

- 不要扩内容池
- 不要先做漂亮 UI
- 不要先做最终美术
- 不要在第 1 周就追求 Boss 完整战斗
- 不要让“配置表读取”拖慢主循环开发

首周的唯一核心目标就是：

把 `前 3 波 + 商店` 跑通。



如果你现在就开工，直接按这个顺序推进就行。
你首周最关键的目标不是把所有内容做完，而是把 前 3 波 + 商店 跑通。
