# 土豆兄弟猫咪版复刻需求 List

## 文档目的

这份 List 用于指导“土豆兄弟猫咪版”的后续完整开发推进，既是需求清单，也是阶段开发基线。

后续所有环节建议围绕这份文档推进：

- 玩法原型
- 美术与角色生产
- 数值设计
- UI 与交互
- 内容配置
- 测试验收

## 一、项目目标

### 1.1 项目定位

复刻一款受《土豆兄弟》启发的猫咪主题俯视角竞技场生存类肉鸽游戏。

项目目标不是简单替换美术，而是在保留核心乐趣的前提下，建立一套完整的“猫咪角色体系 + 猫咪世界观 + 猫咪视觉风格 + 猫咪内容配置”。

### 1.2 核心体验目标

- 玩家能在短时间内进入战斗并获得持续输出快感
- 玩家能通过角色差异感受到明显的流派变化
- 玩家能通过武器、道具、成长路线形成构筑乐趣
- 玩家能明显感知“猫咪版”与原版在角色气质和美术表达上的差异
- 每局流程清晰、反馈直接、节奏干脆，不拖沓

### 1.3 复刻边界

必须优先复刻的内容：

- 单局战斗主循环
- 自动攻击与移动生存
- 角色差异化开局
- 武器成长与商店刷新
- 波次制战斗
- 敌人刷新与精英/Boss节奏
- 结算与失败重开

前期可以不做或延后做的内容：

- 完整剧情系统
- 复杂多人模式
- 大规模剧情演出
- 过度复杂的养成外循环
- 高成本过场动画

## 二、核心玩法需求

### 2.1 核心循环

必须明确并落地的战斗主循环：

1. 选择角色
2. 进入波次战斗
3. 击杀敌人并拾取资源
4. 波次结束进入商店
5. 购买武器/道具/属性
6. 进入下一波
7. 达成胜利或死亡结算

### 2.2 战斗基础规则

必须定义清楚：

- 玩家是纯移动操作，还是允许主动技能
- 攻击是否全自动
- 武器攻击方向是否自动索敌
- 近战与远程的命中规则
- 暴击、闪避、护甲、吸血、攻速、幸运等属性公式
- 受击、击退、无敌帧、死亡判定规则
- 地图边界与障碍规则

### 2.3 波次系统

必须确定：

- 每波时长
- 总波次数
- 普通波、精英波、Boss 波的分布
- 每波敌人种类和刷新密度
- 波次难度增长规则
- 中途掉落箱子或特殊奖励机制

### 2.4 商店与构筑系统

必须具备：

- 波次后固定商店阶段
- 武器购买
- 道具购买
- 属性成长购买
- 锁定功能
- 刷新功能
- 合成/升级规则
- 稀有度规则

需要尽早定义：

- 商店池如何按波次扩容
- 武器是否有限制职业适配
- 道具是否存在流派标签
- 角色专属道具是否存在

## 三、猫咪版差异化需求

### 3.1 主题定位

猫咪版不能只停留在换皮，必须体现以下差异：

- 角色原型来自猫咪品种或野生猫科
- 武器、道具、敌人命名具备猫咪世界观语义
- UI 风格、图标、装饰元素与猫主题统一
- 角色动作、待机、受击和死亡反馈带有猫科特征

### 3.2 角色体系需求

角色系统必须包含：

- 角色基础属性
- 角色被动效果
- 角色开局限制
- 角色适配武器倾向
- 角色视觉标签
- 角色猫咪品种映射

建议后续统一为以下角色设计模板：

- 角色名
- 对应猫咪品种/猫科
- 角色定位
- 开局属性
- 被动效果
- 禁用或弱化属性
- 推荐流派
- 美术关键词
- 动作关键词
- 音效关键词

### 3.3 美术风格需求

必须提前明确：

- 是偏可爱 Q 版，还是偏夸张粗粝卡通
- 角色头身比
- 武器尺寸夸张度
- 敌人血腥程度
- 配色风格
- UI 视觉层级
- 地图材质风格

建议统一的猫咪版视觉原则：

- 角色识别第一
- 武器轮廓第二
- 弹道与受击反馈第三
- 装饰细节不要压过战斗信息

## 五、后续开发必须收集的信息

这是最关键的一部分。后续每推进一个模块，都要先确认相关信息是否完整。

### 5.1 产品定义信息

必须先确认：

- 目标平台是什么
- 引擎是什么
- 输入方式是什么
- 是否支持手柄
- 是否支持移动端
- 是否单机
- 是否需要存档
- 是否需要成就系统

### 5.2 对标拆解信息

必须整理清楚：

- 原作单局时长区间
- 原作节奏节点
- 原作战斗反馈强项
- 原作角色差异设计方式
- 原作商店和构筑的爽点来源
- 原作失败后的重开成本

注意：

- 这里可以参考原作机制节奏
- 不建议直接照搬原作美术、文本、图标和音频资源
- 猫咪版应建立自己的命名体系与美术体系

### 5.3 角色设计信息

每个角色至少要补齐：

- 角色名称
- 对应猫咪品种
- 核心卖点
- 开局属性
- 被动
- 限制项
- 推荐武器池
- 推荐流派
- 视觉关键词
- 立绘关键词
- 动作表现关键词

### 5.4 武器设计信息

每把武器至少要补齐：

- 武器名称
- 武器类别
- 攻击形式
- 伤害
- 攻速
- 范围/弹道
- 击退
- 稀有度
- 升级规则
- 适配角色
- 视觉表现关键词

### 5.5 道具设计信息

每个道具至少要补齐：

- 道具名称
- 道具稀有度
- 基础效果
- 叠加规则
- 是否触发型
- 是否有负面效果
- 对应流派标签
- 美术图标关键词

### 5.6 敌人与关卡信息

必须明确：

- 敌人类型分类
- 每类敌人的移动方式
- 每类敌人的攻击方式
- 每类敌人的危险等级
- 刷新波次
- 掉落规则
- Boss 技能机制
- 地图尺寸
- 地图是否多主题切换

### 5.7 美术生产信息

必须提前定稿：

- 角色像素尺寸或原画尺寸
- 动画帧数标准
- UI 图标尺寸规范
- 字体风格
- 颜色体系
- 地图资源规格
- 特效风格
- 导出命名规范

### 5.8 技术实现信息

必须明确：

- 工程目录结构
- 资源命名规范
- 配表格式
- 存档格式
- 数据热更新需求
- 战斗逻辑是否数据驱动
- 是否需要 Mod 扩展结构
- 调试工具与日志方案

### 5.9 数值信息

必须尽早形成表格：

- 角色初始属性区间
- 敌人生命值成长曲线
- 武器伤害成长曲线
- 商店经济曲线
- 道具出现概率
- 稀有度收益曲线
- 幸运属性收益曲线
- 关卡难度曲线

## 六、开发阶段推进 List

### 阶段 A：立项与原型准备

交付物：

- 项目目标确认
- 玩法边界确认
- 技术栈确认
- 角色首批名单
- 武器首批名单
- 核心玩法草图

验收标准：

- 明确“先做什么，不做什么”
- 至少可以列出首个可玩版本范围

### 阶段 B：可玩原型

交付物：

- 单角色可操作
- 自动攻击
- 单地图
- 基础敌人刷新
- 波次结束进入商店
- 武器购买和属性成长

验收标准：

- 能完成一局基础循环
- 战斗、商店、下一波切换无阻塞

### 阶段 C：核心玩法 Alpha

交付物：

- 多角色
- 多武器
- 多种敌人
- 精英/Boss
- 道具系统
- 初版 UI
- 初版音效

验收标准：

- 不同角色已有明显玩法差异
- 已具备反复游玩的基础

### 阶段 D：内容扩充

交付物：

- 完整角色池第一版
- 完整武器池第一版
- 完整道具池第一版
- 地图主题第一版
- 完整猫咪风格文案

验收标准：

- 内容足够支撑多轮测试
- 各流派能跑通

### 阶段 E：打磨与平衡

交付物：

- 数值平衡迭代
- 交互优化
- 动画与特效优化
- 性能优化
- 新手引导优化

验收标准：

- 爽感稳定
- 主流流派不过强或过弱
- 新玩家能快速理解玩法

### 阶段 F：上线准备

交付物：

- 最终 UI
- 最终文案
- 设置项
- 存档
- 成就或统计
- BUG 清单收敛

验收标准：

- 可持续稳定游玩
- 关键崩溃和阻塞问题清零

## 七、开发时需要重点注意的方面

### 7.1 不要先做重内容，先做强循环

如果战斗主循环不成立，猫咪主题做得再漂亮也没有意义。

优先顺序应该始终是：

- 手感
- 节奏
- 信息反馈
- 构筑乐趣
- 内容扩充

### 7.2 不要只复刻表面，要复刻节奏结构

真正需要复刻的是：

- 进入战斗的速度
- 击杀与掉落反馈
- 波次结束后的购物决策
- 构筑逐渐成形的爽感

不是简单地把角色、武器、UI 名字改成猫。

### 7.3 猫咪主题需要统一，不要局部猫化

需要统一的内容：

- 角色命名
- 道具命名
- 武器命名
- 怪物命名
- 地图元素
- 图标与 UI 装饰
- 文案口吻

### 7.4 提前建立数据驱动结构

后面角色、武器、道具会非常多，如果前期写死逻辑，后面会失控。

建议尽早把以下内容做成配置驱动：

- 角色
- 武器
- 道具
- 敌人
- 波次
- 掉落

### 7.5 复刻时要注意版权边界

建议：

- 借鉴玩法结构，不直接复制原版资源
- 不直接使用原版角色图、道具图、音频
- 不直接照搬原版文本命名
- 猫咪版应该形成自有素材与命名体系

## 九、当前可直接执行的下一步

如果要按这份 List 往下推进，建议下一步优先做以下三件事：

1. 先定 `技术栈 + 目标平台 + 输入方案`
2. 先出 `首批 8-12 个猫咪角色设计表`
3. 先出 `首个可玩版本的武器、敌人、波次最小闭环`

这三件事决定后，项目才算真正进入可执行阶段。
